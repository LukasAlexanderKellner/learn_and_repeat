# Learn & Repeat

Learn & Repeat is a local-first PDF learning workflow. It converts course PDFs
into Markdown, extracts chapter-level learning material, stores searchable
embeddings in PostgreSQL with pgvector, and presents due chapters in a NiceGUI
web app using a spaced-repetition schedule.

## Features

- PDF OCR and diagram extraction with Google Gemini.
- Markdown cleanup that preserves equations, headings, and image references.
- Chapter-aware Markdown parsing with smaller chunks retained for embeddings.
- Local embeddings generated by Ollama with `nomic-embed-text`.
- PostgreSQL storage for documents, chapters, chunks, vectors, and review state.
- A NiceGUI review interface with a 0-5 rating scale and SM-2 scheduling.
- Make targets for starting/stopping services and running the ingestion workflow.

## Requirements

- macOS or Linux
- Python 3.10 or newer
- Docker Desktop or Docker Engine with the Compose plugin
- [`uv`](https://docs.astral.sh/uv/) (or Python's built-in `venv` and `pip`)
- Ollama, with the `nomic-embed-text` model available locally
- A Google Gemini API key for PDF OCR

## Setup

Clone the repository and create a virtual environment:

```bash
uv venv --python 3.13
uv pip install --python .venv/bin/python -r requirements.txt
```

Create the local database configuration:

```bash
cp docker/.env.example docker/.env
```

Edit `docker/.env` and set a unique local PostgreSQL password. This file is
ignored by Git and must not be committed.

Create `src/ocr/.env` and add your Gemini API key:

```dotenv
GEMINI_API_KEY=your_gemini_api_key
```

This file is also ignored by Git. Never commit API keys or other credentials.

Start Ollama and make sure the embedding model is installed:

```bash
ollama pull nomic-embed-text
```
Or replace the existing local embedder with a local or cloud-embedder of your choice. 

## Input and output

- Put source PDFs in `data/input_pdf/`.
- OCR-generated Markdown and extracted image assets go to `data/output_markdown/`.
- `data/state.json` records source PDFs already processed by the OCR pipeline.
- PostgreSQL stores the imported chapters, chunks, embeddings, and review
  schedules in the `pgdata` Docker volume.

Generated data and local secrets are not intended to be committed.

## Commands

Run commands from the repository root:

```bash
make help
```

| Command | Description |
| --- | --- |
| `make start_app` | Start PostgreSQL, wait for it to become healthy, then start the web UI. |
| `make stop_app` | Stop the web UI and then stop PostgreSQL without deleting its data. |
| `make start_db` | Start PostgreSQL. |
| `make stop_db` | Stop PostgreSQL without deleting the database volume. |
| `make start_webui` | Start the NiceGUI app in the background. |
| `make stop_webui` | Stop the NiceGUI app started by the Makefile. |
| `make ingest` | OCR PDFs not recorded in `data/state.json`, then import cleaned Markdown and generate embeddings. |

The web UI is available at `http://localhost:8080` by default. Set `APP_PORT`
in `docker/.env` to use a different port.

The database is published on host port `5433` and listens on container port
`5432`. The Makefile starts the web UI and database separately; run
`make ingest` once to process and import material before starting a review
session.

The web UI writes each rating to PostgreSQL immediately. Closing the browser
does not discard a submitted rating.

## Ingestion behavior

`make ingest` performs these steps:

1. Start PostgreSQL and wait for its health check.
2. Run the cloud OCR pipeline for PDFs not yet listed in `data/state.json`.
3. Split cleaned Markdown into chapters using level-one and level-two headings.
4. Split chapter content into bounded chunks and generate an embedding for each
   chunk with Ollama.
5. Store chapters, chunks, embeddings, and one spaced-repetition review per
   chapter in PostgreSQL.

Markdown files already present in the database are skipped by source path.
If a PDF has already been recorded in `data/state.json`, the OCR stage will
skip it. To reprocess a document, update the state file deliberately and
consider that the Markdown output and database ingestion have separate
duplicate checks.

## Database lifecycle

The PostgreSQL service uses the `pgvector/pgvector` image. The schema in
`database/init.sql` is applied when PostgreSQL first initializes a new,
empty data volume. Changing that file does not alter an existing database
volume; use a migration for schema changes.

Stopping PostgreSQL preserves its data. Removing the Compose volume permanently
deletes the database, including all review progress. Do not run this command
unless you intentionally want to reset all stored data:

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yml down -v
```

## Tests

Run the unit tests with:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

The tests cover chapter and chunk splitting, database configuration, ingestion
behavior, SM-2 calculations, and review querying. They do not require live
Gemini, Ollama, or PostgreSQL services.

## Project layout

```text
database/       PostgreSQL schema
docker/         Compose configuration and environment template
src/app/        NiceGUI web application
src/database/   Database connection and Markdown ingestion
src/ocr/        PDF OCR pipelines and Markdown refinement
src/processing/ Markdown chapter/chunk parsing and Ollama embeddings
src/repetition/ Review queries and SM-2 scheduling
tests/          Unit tests
data/input_pdf/ Source PDFs (local data)
data/output_markdown/ Generated Markdown and image assets (local data)
```

## Privacy and security

PDFs, extracted Markdown, review content, and embeddings are stored locally by
default, but PDF pages are sent to Google Gemini during cloud OCR. Review the
provider's data handling terms before processing sensitive material. Keep
`.env` files, API keys, and personal documents out of public commits.
